01 · Creating observables

Where do streams come from?

Before you can map, filter or switch anything, you need an Observable. Creation functions like of and from turn everyday things (values, arrays, Promises) into streams.

In plain language

An Observable is a show. subscribe() is the play button.

An Observable describes values that arrive over time. It sits on the shelf doing nothing until someone presses play with subscribe(). Creation functions are the quick ways to put a show on the shelf: of and from for values you already have, interval for a clock, throwError for a failure.

Real-world example

A music playlist

of(song1, song2) is "queue exactly these songs". from(album) is "open this album and queue every track inside". Nothing plays until you press play.

First, the vocabulary

A stream can only tell you three things

next

"Here is a value." It can happen zero, one or many times.

error

"Something went wrong." The stream ends right here, and no more values come.

complete

"I'm finished, no more values." Some streams, like a clock, never complete.

The mix-up everybody makes

of vs from

Both give you an Observable, but they treat what you hand them differently.

of(…)from(…)
You give itValues, listed one by oneOne thing that contains values: an array, a string, a Promise
With [1, 2, 3]Emits 1 value: the arrayEmits 3 values: 1, then 2, then 3
Think of it as"Emit exactly what I list""Open it up and emit what's inside"

Rule of thumb: if you'd write a for…of loop over it, use from. If you're listing the values yourself, use of.

In real apps

Where you'll actually use these

of(mockUsers)

Fake data while the backend isn't ready

An HTTP call returns a whole list as one value, so of(listOfUsers) (one emission) is the right stand-in. It's also common in tests.

catchError(() => of([]))

A safe fallback when a request fails

If loading products fails, switch to an empty list instead of crashing the screen. You'll use this in the Errors lesson.

from(files).pipe(concatMap(upload))

Handle a list one item at a time

Turn a list of files or IDs into a stream, then upload, fetch or process them one after another.

from(navigator.clipboard.readText())

Use a Promise inside a pipeline

Browser APIs and many libraries return Promises. from lets you mix them with the rest of your RxJS code.

interval(5000)

Poll an API every 5 seconds

Use timer(3000) for a one-time delay, like hiding a toast message after three seconds.

fromEvent(button, 'click')

Turn clicks and keys into streams

Mouse moves, key presses and scrolling become streams you can debounce, filter and combine. You'll see this in the Performance lesson.

Check yourself

Can you predict it? Think first, then open the answer.

What does of([1, 2, 3]) emit?

One value: the whole array [1, 2, 3], and then complete. of doesn't unpack anything. To get three separate numbers, use from([1, 2, 3]) or of(1, 2, 3).

You write const data$ = of(1, 2, 3); and never call subscribe. How many values are emitted?

None. Observables are lazy: until someone subscribes, no work happens. (The $ at the end of the name is just a naming habit for "this is an Observable".)

When does interval(1000) complete?

Never. It ticks forever, so you either add take(n), or you must unsubscribe when you're done, or the timer keeps running. The Performance lesson shows what happens when you forget.
