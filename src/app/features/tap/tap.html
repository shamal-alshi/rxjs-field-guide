02 · tap

How do I peek at a stream without touching it?

tap lets you look at every value passing by and do something on the side, like logging it or switching a spinner on, while the values continue on their way exactly as they were.

In plain language

tap is a security camera on a conveyor belt.

The camera watches every parcel and can record or raise an alarm, but it never changes, removes or adds a parcel. In RxJS terms, tap runs your function for each value (a side effect) and then passes the original value along untouched.

Real-world example

A shop receipt printer

Every sale passes through the till. The printer prints a receipt on the side, but the sale itself, its items and total, goes on exactly the same.

Good to know

tap can watch next, error and complete

Pass a single function to watch values, or pass an object to watch all three things a stream can tell you.

Every box in this guide's animations is built from this exact idea. A small helper called flowTap wraps tap to record what it sees, and the page replays it slowly so you can follow along.

In real apps

When to reach for tap

tap(console.log)

Debugging: "where did my value go?"

Drop a tap between two operators to see what is flowing through that spot. Remove it when you're done.

tap(() => loading.set(true))

Loading flags

Turn a spinner on before a request starts and off when the response arrives, as in the lab above.

tap(order => analytics.track(order))

Analytics and logging

Report "user searched for X" without touching the data that continues to your screen.

tap(cart => localStorage.setItem(…))

Saving as you go

Store the latest value in the browser while the same value keeps flowing to the UI.

Watch out

Four mistakes to avoid

  1. Using tap to change a value. Its return value is ignored. Use map for that.
  2. Expecting tap to run on its own. No subscriber means no run at all, because Observables are lazy.
  3. Hiding important logic inside it. If your app needs the result of an action, do it in subscribe or a proper operator. Keep tap for small side jobs.
  4. Letting it throw. If your function inside tap throws an error, the whole stream fails.

Check yourself

Predict first, then open the answer.

What does the subscriber receive from of(1, 2).pipe(tap(n => n * 100))?

Just 1 and 2. tap ignores what your function returns, so the values pass through unchanged.

You write source$.pipe(tap(console.log)) and never subscribe. What gets logged?

Nothing. Without a subscriber the pipeline never runs, so tap never gets a value to look at.

You want to turn prices in dollars into prices in rupees. tap or map?

map. You're changing the value, and only map (or another transforming operator) can do that.
