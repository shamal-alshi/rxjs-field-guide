02 · Cold vs. hot streams

One stream, or one per listener?

A cold Observable starts its work for each subscriber. A hot, shared Observable lets multiple subscribers listen to the same work already in progress.

In plain language

Cold is “make me one”; hot is “join the one that’s running.”

Each subscription to a cold stream is like placing a separate order. Sharing operators let listeners ride the same request instead of starting another one.

Real-world example

Prevent duplicate API calls

If a page header and chart both subscribe to the same cold HTTP stream, the server may get two requests. Sharing can make one request serve both.

What to notice

Plain cold streams make a new request per subscriber. share() shares an in-flight request but forgets it after completion. shareReplay(1) can also give a late subscriber the last result.
